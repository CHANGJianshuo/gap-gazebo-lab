# 常建烁的运动规划方案

已经实现：**多初值 KDL IK + Ruckig 直接轨迹 / 五次 B 样条 + 必要时 RRT-Connect + 全模型碰撞、动力学和控制器插值验证**。这是候选比较方案，目标是选出在本次约束下最快的已验证轨迹。实际结果见 [验证记录](../VALIDATION.md)。

## 从零理解输入和输出

六轴机械臂的状态 `q` 是六个关节角。末端 TCP 的“位姿”包含位置和朝向。IK（inverse kinematics，逆运动学）回答“这个末端位姿对应哪些关节角”；轨迹 `q(t)` 回答“每个时刻六个关节怎样运动”。只返回 IK 解不能告诉控制器怎样避障到达它。

| 环节 | 做什么 | 当前实现 |
| --- | --- | --- |
| IK | 寻找可达、无碰撞的终点关节姿势 | KDL，最多 24 个外层初值、保留最多 6 个不同候选；不是穷尽解析解 |
| 路径 | 决定中间经过哪些姿势 | 优先尝试直接连接；抓放用末端直线；必要时 RRT-Connect 绕障 |
| 优化 | 比较逆解、减少不必要的路径变化 | 多候选比较；OMPL 简化后的路径或连续 IK 路径拟合五次 B 样条 |
| 时间 | 决定加减速与到达时刻 | Ruckig 生成限 jerk 的点到点轨迹；样条用导数控制点界确定保守时长 |
| 执行验证 | 检查最终曲线和实际响应 | FCL、全树 Newton–Euler、实际 JTC 插值、Gazebo 关节和接触反馈 |

同一个夹爪位置可能有“肘高”和“肘低”等不同姿势。先找一个 IK 就固定下来，可能浪费后续运动时间，因此本方案把不同 IK 解生成的**整条轨迹**放在一起比较。

## 多项式和 B 样条在哪里

它们是曲线表示方法，不是固定的一个独立阶段。无人机常用它们表达位置 `x(t)`；本项目用它们表达六维关节角 `q(t)`，通过正运动学得到末端轨迹。机械臂额外要考虑整条连杆、自碰撞、奇异姿态、关节范围以及随姿态变化的负载力矩。

五次多项式 `q(t)=a0+a1 t+…+a5 t⁵` 可以满足起止位置、速度、加速度六项边界条件。五次 B 样条把多个多项式片段连接起来，用控制点更方便地改变形状；本项目重复端部控制点以保证起止速度、加速度为零。

样条以进度 `u∈[0,1]` 表达，执行时间是 `t=T u`。于是速度除以 T，加速度除以 T²，jerk 除以 T³。使用导数控制点的凸包界，能保守约束整条样条的关节导数。这个性质**不能自动保证非线性的碰撞和动力学约束**，所以还要对最终曲线重新验证。[Drake 的同类 B 样条表示](https://drake.mit.edu/doxygen_cxx/classdrake_1_1planning_1_1trajectory__optimization_1_1_kinematic_trajectory_optimization.html)

当前实现采用控制点线性求解、几个控制点数量的候选比较、时间界和力矩超限后的时长放宽；没有把完整碰撞与动力学问题交给一个声称全局最优的非线性优化器。

## 为什么这样选

- 空间畅通时，直接 Ruckig 避免不必要的采样路径和每段停顿，并同时考虑六关节的速度、加速度与 jerk。
- 接近把手、抬升、下放、撤离必须保持末端近似直线。先每 4 mm / 0.02 rad 连续求 IK，再拟合样条，最终要求位置偏离不超过 1.5 mm、朝向偏离不超过 0.018 rad。
- 直接连接不可用时再运行 RRT-Connect。拟合后的样条可能切进障碍，因此拟合成功也不能跳过最终碰撞检查。
- 已抓住的电池成为附着碰撞物和动力学负载。搬运过程中约束电池倾斜不超过约 20°，检查电池底面高度。
- 在所有通过检查的候选中选择执行时间最短者，同时保留被拒绝候选及原因，方便继续调优。

先前的 TOTG→Ruckig 是通用基线建议。当前实现直接生成可验证的分段多项式/样条轨迹，没有再串联 TOTG，避免重复改变已经检查过的轨迹表示。Ruckig 的时间最优性质有其问题假设，不能扩展成“整个带障碍机械臂任务全局最优”。[Ruckig 文档](https://docs.ruckig.com/)

## 如何让规划支持控制

输出每点的 q、速度、加速度和时间，保留主要切换时刻与样条结点。相距不足 0.5 ms 的时间点会合并，避免微小分母放大浮点误差；随后检查插值曲线的速度界、加速度与 jerk 极值，并按需要增加时长。最终限制位置表示误差不超过 10⁻⁷ rad，而不是让控制器根据稀疏位置点另外猜一条曲线。[JTC 轨迹表示](https://control.ros.org/humble/doc/ros2_controllers/joint_trajectory_controller/doc/trajectory.html)

力矩前馈使用 `τ=M(q)q̈+C(q,q̇)q̇+g(q)`。它告诉电机“完成参考运动大约需要多大力矩”，PID 再根据实际误差补偿。相机偏置、锁扣和电池惯量都参与计算；Gazebo 端最终按官方 URDF 的电机力矩限幅，禁止无限力矩推动轨迹。

候选一般要求预测力矩不超过限值的 82%，为反馈控制留余量。实测同时记录控制器输出力矩，不能只看预测值。加速度与 jerk 限值是仿真调试参数，还需要根据真实 S3 控制接口、末端质量和跟踪效果标定。

## “最优”的准确含义

这里优化的是**已知场景、已知负载和运动约束下的候选轨迹执行时长**。任务顺序和各步骤等待时间属于 SJM 的调度层。更快的计算也有价值，因此另外报告规划墙钟耗时和完整流程时间。

最终 FCL 检查最大时间步 4 ms，并在关节速度较高时缩小步长，目标关节增量 0.003 rad。这是有限分辨率检查，不是数学上的连续碰撞证明；Gazebo 另外每 1 ms 记录实际接触。通过的证据仅覆盖所记录的模型、场景和运行。

继续提升应基于同一组测试：比较总完成时间、成功率、跟踪误差、峰值力矩与最小净空，再考虑更快 IK、重复路线缓存、TOPPRA/动力学时间优化、TrajOpt 或 GPU 并行优化。不能仅凭算法名字判断哪一个在本比赛中最好。
