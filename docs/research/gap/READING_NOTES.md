# GaP 阅读笔记：让机器人自动组织和改进操作流程

阅读版本：`arXiv:2607.05369v1`，2026-07-06；核对日期：2026-09-05。[原文](paper/gap_2607.05369v1.md) · [PDF](paper/gap_2607.05369v1.pdf) · [S3 实施建议](S3_RESEARCH_PLAN.md)。

**我的建议是把 GaP 用于 S3 的操作策略层：根据当前情况选择技能、设置参数、执行检查并处理失败，继续由现有运动规划模块生成真实可执行的轨迹。** 论文已经展示机械臂实机应用，因此我们有价值的问题是：它能否在这套电池搬运系统里，以可控的试验成本提高完整任务可靠性和效率。

## 1. 先用搬电池理解 GaP

原先程序的流程是：到把手上方 → 下降 → 合锁扣 → 抬升 → 搬运 → 放下 → 松扣 → 上撤。程序员提前决定每一步以及失败后怎么办。

GaP 把这些步骤表示成**可执行的技能图**。图中一个方框可以读取电池位姿、计算抓取目标、调用规划器或检查锁扣；连线同时表达“数据交给谁”和“满足什么条件才能继续”。大模型可以生成这张图，再根据仿真失败记录修改它。[论文第 3、4 节](https://arxiv.org/html/2607.05369v1#S3)

例如第一次下降后锁扣没有连接，反馈指出 TCP 没进入把手允许范围。改进可以是重新读取当前状态、修正抓取坐标转换、重新规划接近动作，并限制重试次数。是否真的扣住，要由仿真状态检查。

这里的 policy 指“给定当前情况，决定做什么”的策略。图中的节点可以调用传统算法，也可以调用学习模型。GaP 所研究的图是执行流程与数据依赖的表示；IK 和轨迹求解仍由技能内部的算法承担。

| 概念 | 在我们的系统里意味着什么 |
| --- | --- |
| 技能 | 一个输入、输出和失败条件明确的可调用功能，例如规划到目标位姿 |
| 子图 | 完成一个阶段的若干技能，例如对准并扣住一块电池 |
| 条件边 | 根据实际结果走不同后续步骤，例如抓住才抬升 |
| 技能库 MORSL | 供策略图选择的积木；论文初始版本列出 51 项技能 |
| rehearsal，仿真排练 | 在多组初始条件中实际跑图，收集错误，修改后重跑 |
| self-learning，自学习 | 此文主要指迭代改进图结构、代码与参数；不要求训练神经网络权重 |

这些解释对应[论文第 4 节及附录 D、E](https://arxiv.org/html/2607.05369v1#S4)。

## 2. 为什么研究“有变化的固定工位”

论文称之为 **Variational Automation，VA**：工作台、机器人和相机已知，物体类别与可能出现的位置范围有界，但每次物体摆法、几何或任务指令可以变化。例如同一个工位持续处理摆放不同的商品。[论文第 2、3 节](https://arxiv.org/html/2607.05369v1#S2)

我们的 S3、电池 CAD、底图和锁扣已知，很适合先做这个方向。若始终只执行完全相同的 CAB 场景，人工流程本来就能做好，难以显现自动改图的价值。应保留比赛原场景作为回归测试，再建立明确标注的研究变体，研究已知范围内的变化。

第一阶段继续使用完美真值输入。这样，如果实验改善了，就能较清楚地归因于操作策略或规划接口；后续接入 D435i 视觉后，再单独研究感知误差。

## 3. 论文系统怎样工作

```mermaid
flowchart LR
  A[任务描述、工位与技能说明] --> B[编排 Agent 分解任务]
  B --> C[技能 Agent 生成子图]
  C --> D[接口与图结构检查]
  D --> E[仿真执行多组任务实例]
  E --> F[检查结果并分析失败]
  F --> C
  F --> G[通过验证后固定策略图]
  G --> H[图执行器反复调用机器人技能]
```

这是基于论文第 4 节绘制的简化示意。作者的图生成与优化框架允许多个 Agent 分工；执行器依据图调用技能。**离线生成与机器人实时控制是两个时间尺度。** 我们的控制器每 2 ms 更新一次，持续跟踪轨迹；大模型更适合在执行前生成图、在一轮实验后分析失败。若图中显式包含 VLM/LLM 技能，执行期间仍可能有模型推理耗时。[论文第 4 节](https://arxiv.org/html/2607.05369v1#S4)

作者的“内部仿真”使用 Isaac-Lab 做排练。我们已有 Gazebo 物理场景，可以研究同样的生成—执行—反馈—改图方法；这属于对 S3/Gazebo 的适配实验，应如实说明与作者原实验环境的区别。

## 4. 与你已经做的运动规划怎样配合

| 层次 | 需要回答的问题 | 主要输出 |
| --- | --- | --- |
| GaP 操作策略 | 现在做哪一步？用哪种接近姿态？失败后怎么恢复？ | 技能调用、参数、分支和任务状态 |
| 运动规划 | 在当前负载与障碍下，怎样到达目标又快又可行？ | 带时间、速度、加速度和力矩信息的关节轨迹 |
| 控制执行 | 电机实际能否跟上这条轨迹？ | 实际关节状态、执行结果与误差 |

所以，我们现有的多初值 IK、Ruckig、五次 B 样条、RRT-Connect 后备、碰撞和动力学验证都能继续使用。GaP 可以调整接近高度、抓取目标候选、搬运方式或恢复步骤；“这段动作每个时刻转多少度”仍由规划器和控制器解决。[本项目已实现接口](../../architecture/INTERFACES.md)

论文的 USB-C 实验尤其值得读：作者把 `align`、`touch`、`insert`、`extract` 四类 ROS 技能接到图中，等待技能返回状态，再决定后续步骤。这证明接入既有 ROS 技能符合原方法。我们仍需要实现针对 S3 的适配器。[论文第 5.6 节、附录 B](https://arxiv.org/html/2607.05369v1#A2)

## 5. 实验到底说明了什么

以下均为**论文作者报告的结果**，不是本项目复现。成功率的分母必须分清。

| 证据 | 作者报告 | 对本项目的启发 |
| --- | --- | --- |
| 仿真购物任务，表 1 | 在其 VA 变化场景中 GaP 多项得分为 0.93–0.99；原始 LIBERO 一列 MolmoAct2 为 0.97、GaP 为 0.95 | 有变化的任务值得测试，单一固定场景不保证受益 |
| 实机商品分拣，表 2 | GaP 25/25，TipTop 8/25；单次抓放平均 67 s 与 95 s | 在特定设置中能提升整流程效率，不能直接外推到我们的 S3 |
| 爆米花任务，第 5.5 节 | 仿真经 10 轮改进，从约 33% 提升到 94%；最终实机 18/20 | 反馈驱动的改进是应重点验证的机制 |
| 实机 USB 插入，第 5.6 节、表 3 | 单次插入合计 121/130；其中升序任务逐端口 32/35，但完整序列只有 2/5 | 单动作成功率高，不等于整个长任务可靠 |
| 洗箱仿真，第 5.7 节 | GaP 143/150，人工图 148/150；平均时长约 179.13 s 与 176.47 s | 人工方案可以更快、更可靠，GaP 的价值还可能在降低编程与调参工作量 |

来源：[论文第 5 节及表 1–4](https://arxiv.org/html/2607.05369v1#S5)。表 4 显示经过取整的数值，上表采用第 5.7 节正文中的分子、分母和小数。

阅读这些结果时还要注意四点。

1. **任务信息不同会影响比较。** 作者明确说明 CaP-X 仅获得初始图像和指令，而 GaP 使用已知工位与几何信息；这部分更适合作为其设置下的比较，不能据此宣称普遍压倒另一类方法。
2. **部分“成功率”是物体级得分。** 装篮任务统计六次尝试中成功放入的物体比例，例如实机 28/30；它不等于整篮任务 93% 次数全部成功。
3. **并非所有表格展示了自学习收益。** 购物与装篮的初始图已表现较好，作者没有在这些任务上做 self-learning。爆米花案例才直接展示迭代改图的过程。
4. **生成失败与物理失败应分别统计。** 去掉图结构或改为单 Agent 的消融在作者设置中出现接口、语法和静态验证失败；结果不能直接解释为单 Agent 在理论上无法解决这些动作。

依据：[论文第 5.2–5.5 节](https://arxiv.org/html/2607.05369v1#S5.SS2)。

## 6. 它能否给出“公认最优”的轨迹

**论文没有提供这样的保证。** 它展示一种可迭代改进的机器人程序生成与执行方法。任务图选择、抓取位姿、碰撞避让和动力学约束共同构成复杂搜索问题，实验中成功率与吞吐量的改善不构成全局最优证明。[论文第 3 节的优化问题与第 6 节局限](https://arxiv.org/html/2607.05369v1#S6)

对我们最有用的思路是：先守住可行性和无非预期碰撞，再减少失败、等待和多余动作。连续轨迹已经很快时，重试一次或重新规划一次可能比压缩几十毫秒运动更影响整场成绩。这个判断需要在同一 S3 场景里测量。

作者也指出，现有结果尚未达到工业可靠性和高吞吐需求，VLM 推理与 IK 等步骤仍耗时，多数任务集中于准静态操作。不能把本文看成通用工业部署已经解决的证据。[论文结论](https://arxiv.org/html/2607.05369v1#S6)
